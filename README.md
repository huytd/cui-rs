# cui-rs

Rust bindings to [CUI](https://github.com/yappologistic/CUI), the immediate-mode
UI component library for C. Write native GUI apps in Rust with CUI's
components: buttons, inputs, menus, dialogs, tables, charts, markdown, code
blocks and more, in a single native window with no runtime dependencies.

This is a wrapper, not a rewrite. CUI's C sources are vendored as a git
submodule and compiled by Cargo, so tracking a new CUI release is a submodule
bump plus a regenerated bindings file (see [Updating CUI](#updating-cui)).

```rust
use cui::{App, AppDesc, BoxOpts, ButtonOpts, Size};

fn main() -> Result<(), cui::Error> {
    let mut notifications = true;
    let mut clicks = 0;
    App::run(&AppDesc::new("Hello").size(420, 300), |ui| {
        ui.column_with(BoxOpts::new().pad(32.0).gap(16.0).width(Size::FILL), |ui| {
            ui.heading("Hello, CUI", 2);
            ui.switch("Notifications", &mut notifications);
            ui.row_with(BoxOpts::new().gap(8.0), |ui| {
                if ui.button_with("Click me", ButtonOpts::new().primary()) {
                    clicks += 1;
                }
                ui.text(&format!("Clicked {clicks} times"));
            });
        });
    })
}
```

```sh
git clone --recursive https://github.com/huytd/cui-rs
cargo run --example hello
cargo run --example todo
```

## Crates

| Crate | What it is |
|---|---|
| [`cui-sys`](cui-sys) | Raw `unsafe` FFI generated by bindgen from `cui.h`, `cui_app.h` and `cui_render.h`, plus the build script that compiles CUI. Covers all of CUI. |
| [`cui-rs`](cui) (`use cui`) | The safe API: `App`, `Ui`, options builders, `TextBuffer`, `icons`, and `Headless` for windowless rendering. Re-exports `cui-sys` as `cui::sys`. |
| `xtask` | Maintenance commands (`cargo xtask ...`), not published. |

## From C to Rust

CUI's C API maps onto Rust with a few fixed rules, so CUI's own docs apply
directly:

| C | Rust |
|---|---|
| `cui_button(ui, "Save")` | `ui.button("Save")` |
| `cui_button(ui, "Save", .variant = CUI_BUTTON_PRIMARY, .icon = CUI_ICON_CHECK)` | `ui.button_with("Save", ButtonOpts::new().variant(ButtonVariant::Primary).icon(icons::CHECK))` |
| `cui_row(ui, .gap = 8) { ... }` | `ui.row_with(BoxOpts::new().gap(8.0), \|ui\| { ... })` |
| `if (cui_dialog(ui, "Title", &open)) { ... }` | `ui.dialog("Title", &mut open, \|ui, open\| { ... })` |
| `cui_push_id_int(ui, i); ...; cui_pop_id(ui);` | `ui.id_scope_int(i, \|ui\| { ... })` |
| `char name[64]; cui_input(ui, "name", name, sizeof name)` | `let mut name = TextBuffer::new(64); ui.input("name", &mut name)` |
| `cui_textf(ui, "%d items", n)` | `ui.text(&format!("{n} items"))` |
| `CUI_FILL`, `CUI_PX(200)`, `CUI_PCT(50)` | `Size::FILL`, `Size::Px(200.0)`, `Size::Percent(50.0)` |
| `CUI_COLOR_ACCENT`, `CUI_RGB(0x3b82f6)` | `Color::ACCENT`, `Color::rgb(0x3b82f6)` |
| `CUI_ICON_PLUS` | `icons::PLUS` |
| `cui_shortcut(ui, CUI_MOD_PRIMARY, CUI_KEY_K)` | `ui.shortcut(Mods::PRIMARY, Key::K)` |

- Option setters have the C field names, and anything you leave out keeps
  CUI's default, exactly like the C macros.
- Containers take closures, so begin/end always pair up. Containers that may
  be closed (popover, menu, dialog, sheet, accordion, tree, table) run the
  closure only while showing and return `Option<R>`.
- Strings are `&str`. They are copied into a per-frame arena that is reused,
  so a steady UI does not allocate.
- Anything not wrapped yet is one step away: `ui.raw()` gives the `cui_ctx*`
  and `ui.c_str("...")` makes frame-lived C strings for `cui::sys` calls.

## Headless rendering and tests

`cui::Headless` runs CUI with the software renderer, no window or GPU. It
renders to RGBA or PNG and takes synthetic input, which makes UI behaviour
testable in plain `cargo test` (see [`cui/tests/headless.rs`](cui/tests/headless.rs),
which clicks buttons and types into fields):

```rust
let mut h = cui::Headless::new(800.0, 600.0, 2.0);
h.frame(1.0 / 60.0, |ui| { ui.button("OK"); });
h.save_png("shot.png");
```

## Features

| Feature | Default | |
|---|---|---|
| `app` | yes | The window layer (`App`). Turn off to drive CUI from your own engine. |
| `default-fonts` | yes | Embed Inter, Geist and Lucide (~180 KB). |
| `stb-image` | yes | PNG and JPEG loading for `image_load`. |
| `image-all-formats` | | Also BMP, GIF and TGA. |
| `text-shaping` | | Shape static Arabic-script text. |
| `sdl2`, `glfw` | | Use SDL2 or GLFW instead of the native backend (you need the library installed). |
| `bindgen` | | Generate bindings at build time instead of using the committed ones (needs libclang). |

Platform backends: Win32 on Windows, Cocoa on macOS, X11 on Linux/BSD
(needs `libx11-dev`). Rendering uses OpenGL 3.3 and falls back to software.
On Windows, add `#![windows_subsystem = "windows"]` to a GUI app so no console
opens.

## Updating CUI

```sh
cargo xtask update          # move the submodule to upstream HEAD and regenerate
cargo xtask update v1.2.0   # or any tag, branch or commit
cargo test
cargo xtask coverage        # CUI functions the safe crate does not wrap yet
```

`update` prints the upstream log and which public headers changed. The C
sources list comes from CUI's own `CMakeLists.txt`, so new or removed source
files need no change here. New C functions appear in `cui::sys` immediately;
renamed or removed ones fail to compile in the safe crate, which points at
exactly what to fix.

`cargo xtask bindgen` regenerates without moving the submodule, and
`cargo xtask check` (run in CI) fails if the committed bindings or icons are
stale.

A [scheduled workflow](.github/workflows/upstream.yml) runs this daily and
opens a pull request whenever CUI has new commits, with the upstream log, the
header diff, the test result and the coverage count.

Regenerating needs libclang. If clang reports `'stdbool.h' file not found`,
your libclang has no resource headers; point it at any compiler's, e.g.
`BINDGEN_EXTRA_CLANG_ARGS=-I/usr/lib/gcc/x86_64-linux-gnu/15/include`.
